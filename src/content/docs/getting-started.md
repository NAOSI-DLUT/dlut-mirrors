## 本站如何提供镜像

首页清单来自 CERNET 校园网联合镜像站。访问本站镜像路径时，本站返回 HTTP 302 到 CERNET，再由 CERNET 选择高校镜像站；下载文件由最终站点提供。

帮助文档的配置示例直接使用 `https://mirrors.cernet.edu.cn/`，减少一跳，也避免把尚未确定的本站正式域名写进软件源。镜像域名和路径都应保留 HTTPS 与原有大小写。

## 配置前检查

1. 确认操作系统版本、代号和 CPU 架构。
2. 找到正在生效的配置文件并备份。系统配置、用户配置、项目配置与环境变量可能同时存在。
3. 只替换文档指定的地址；不跨发行版或主版本拼接仓库。
4. 保留原 GPG keyring、TLS 和校验和设置。
5. 更新索引或执行文档中的查询命令，检查实际使用的源。

镜像配置会改变后续软件下载来源。若只想测试网络，优先使用包管理器的单次参数，不急着修改整个系统。

## 查看重定向

以 Ubuntu 元数据为例：

```bash
curl -I https://mirrors.cernet.edu.cn/ubuntu/dists/noble/Release
curl -IL --max-redirs 5 https://mirrors.cernet.edu.cn/ubuntu/dists/noble/Release
```

第一条查看入口响应，第二条跟随重定向。不同网络、时间和仓库可能得到不同目标。并非所有软件源都支持 HEAD；必要时对小型元数据执行 GET，不用大型 ISO 做连通性测试。

## 常见错误

| 现象                    | 优先检查                                               |
| ----------------------- | ------------------------------------------------------ |
| 404 / 没有 Release 文件 | 仓库路径、版本代号、大小写、架构和是否已经归档         |
| 503 / 清单暂时不可用    | CERNET 上游是否可达；稍后重试或使用已知可用的官方源    |
| 校验和不符              | 镜像同步窗口、旧索引缓存；等待或换回原源后刷新         |
| 签名验证失败            | 系统时间、发行版 keyring、仓库与系统版本是否匹配       |
| HTTPS 证书失败          | 系统 CA、时间、代理证书；不要关闭证书校验              |
| 找不到软件包版本        | 软件包是否支持该平台、频道是否覆盖、是否刚发布尚未同步 |
| 换源后仍访问旧域名      | 环境变量、项目配置、锁文件或元数据中的独立下载地址     |

不要为了处理暂时故障，统一删除锁文件、关闭签名校验或升级整个发行版。

## 恢复与反馈

按各指南恢复备份或删除本次新增的配置项，再刷新索引。删除用户级设置后，如果仍使用同一地址，应检查项目级配置和环境变量。

反馈时提供仓库名称、操作系统版本、包管理器版本、命令、时间和错误状态码。配置和日志中的访问令牌、账号密码及私有项目路径应先移除。
